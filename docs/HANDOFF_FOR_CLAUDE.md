## 2. 핵심 콘셉트

Race Simulator는 여러 자동차가 동일한 레이싱 트랙을 주행하면서 유전 알고리즘을 통해 점차 운전 능력을 개선하는 시뮬레이터다.

각 자동차는 고유한 신경망을 가지고 있으며, 신경망이 자동차의 조향과 가속 및 제동을 제어한다.

초기 세대의 자동차는 운전 방법을 제대로 알지 못하므로 벽에 충돌하거나 주행 도중 멈출 수 있다.

이후 우수한 자동차의 유전자를 선택하고 교차 및 돌연변이를 반복하면서 다음 세대의 자동차를 만들어낸다.

세대를 거듭할수록 더 멀리 주행하거나 트랙을 완주하는 자동차가 나타날 수 있다.

단, 진화 성능을 인위적으로 조작하거나 학습에 성공한 것처럼 연출해서는 안 된다.

**반드시 실제 유전 알고리즘에 의해 성능이 변화해야 한다.**

## 3. 프로젝트의 핵심 목표

다음 다섯 가지 경험을 제공한다.

### 3.1 진화 과정 시각화

사용자가 자동차들의 실제 주행을 관찰하면서 유전 알고리즘의 작동 원리를 이해할 수 있어야 한다.

### 3.2 직접 진화시키기

사용자가 어떤 자동차의 유전자를 다음 세대에 전달할지 직접 선택할 수 있어야 한다.

### 3.3 완전 자동 진화

사용자가 자동 학습을 실행하면 AI가 자동차 주행, 평가, 부모 선택, 교차, 돌연변이, 다음 세대 생성까지 모든 과정을 자동으로 반복해야 한다.

### 3.4 이전 세대와 성능 비교

금색 챔피언 자동차와 고스트 기능을 통해 진화 성능을 직관적으로 비교할 수 있어야 한다.

### 3.5 실험 재현 및 저장

트랙 시드, 자동차 유전자, 세대별 학습 결과를 저장하고 다시 불러와 실험을 이어갈 수 있어야 한다.

# PART 2. 최종 게임 화면 디자인

## 4. 화면 구성

전체적인 분위기는 완성도 높은 레이싱 게임과 데이터 분석 대시보드의 중간 형태다.

너무 복잡한 전문 소프트웨어처럼 보이지 않아야 한다.

동시에 단순한 학교 과제 수준의 디자인이 아니라 실제 제품처럼 완성도 높은 UI를 목표로 한다.

기본 화면은 다음 세 영역으로 구성한다.

### 왼쪽 패널 — 설정 및 조작

- 자동차 개체 수
- 진화 방식
- 교차 확률
- 돌연변이 확률
- 주행 시작
- 일시정지
- 주행 재개
- 배속 설정
- 건너뛰기
- 자동 학습 시작
- 실험 저장 및 불러오기

### 중앙 — 메인 레이싱 화면

화면에서 가장 넓은 영역이다.

실제 자동차들이 주행하는 2D 트랙을 표시한다.

트랙, 자동차, 체크포인트, 출발선, 금색 챔피언, 고스트, 선택 효과 등을 렌더링한다.

### 오른쪽 패널 — 통계 및 분석

- 현재 세대
- 최고 진행률
- 평균 진행률
- 최고 적합도
- 평균 적합도
- 완주 자동차 수
- 충돌 자동차 수
- 브레이크 정지 자동차 수
- 세대별 성능 그래프
- 최고 자동차 정보
- 고스트 비교 기록

기존 중앙 트랙 화면은 수동 선택, 자동 진화, 주행 종료 상황에서도 동일하게 유지해야 한다.

불필요하게 화면을 새로 만들거나 자동차를 재배열하지 않는다.

## 5. 자동차 디자인

자동차는 **단순하면서도 완성도 높은 2D 탑다운 형태**로 만든다.

너무 사실적인 슈퍼카나 복잡한 3D 렌더링처럼 만들지 않는다.

사용자는 이전에 제시된 자동차 디자인이 지나치게 고급스럽다고 판단했다.

따라서 단순한 실루엣과 세련된 색상, 명확한 윤곽선을 사용하는 방향으로 수정한다.

구체적인 요구사항은 다음과 같다.

1. 모든 자동차는 위에서 내려다보는 형태다.
2. 자동차의 전체 크기는 기존 초기 예시보다 약 30~40% 작게 설정한다.
3. 정확한 크기는 실제 화면 비율에 맞춰 조정할 수 있다.
4. 자동차마다 구분 가능한 색상을 사용한다.
5. 자동차 번호를 표시한다.
6. 차체 방향을 쉽게 구별할 수 있어야 한다.
7. 자동차가 작더라도 클릭으로 선택하기 쉬워야 한다.
8. 불필요한 복잡한 차체 장식을 추가하지 않는다.
9. 실제 물리 충돌 크기와 화면에 보이는 차체 크기가 일관되어야 한다.

기본 자동차는 간결하고 세련되게 만들고, 금색 챔피언만 특별한 시각 효과를 부여한다.

# PART 3. 트랙 시스템

## 6. 트랙의 절대적인 조건

**모든 트랙은 반드시 하나의 길로 이루어진 폐회로형 레이싱 서킷이어야 한다.**

다음 요소는 절대 허용하지 않는다.

- 갈림길
- 지름길
- 함정 경로
- 막다른 길
- 도로 교차로
- 내부 샛길
- 우회 경로
- 트랙의 자기 교차
- 도로가 서로 맞닿아 다른 길로 진입할 수 있는 구조

트랙을 따라 앞으로 주행하면 반드시 다시 출발선으로 돌아오는 형태여야 한다.

어떤 자동차도 경로 선택을 할 필요가 없어야 한다.

모든 자동차는 동일한 길에서 얼마나 멀리, 얼마나 빠르게 진행하는지만 비교한다.

사용자가 과거에 참고 이미지에서 발견했던 트랙 내부의 이상한 길이나 함정 구조는 절대로 생성하지 않는다.

## 7. 트랙 난이도

사용자가 게임을 처음 시작할 때 난이도를 선택한다.

**하 / 중 / 상**

### 하

- 상대적으로 완만한 곡선
- 급격한 방향 전환이 적음
- 초보 자동차가 주행하기 쉬운 구조

### 중

- 다양한 곡선
- S자 커브
- 어느 정도 급격한 방향 전환

### 상

- 더 많은 커브
- 급격한 방향 전환
- 헤어핀 및 복잡한 곡선

난이도가 높아진다고 새로운 경로가 생기는 것이 아니다.

**난이도는 단일 도로의 곡선 형태와 주행 난도로 구분한다.**

## 8. 트랙 크기

트랙은 초기 예시보다 다음과 같이 수정한다.

- 도로 폭을 더 넓게 한다.
- 트랙 전체 길이를 더 길게 한다.
- 자동차는 상대적으로 작게 만든다.

전체 트랙이 중앙 화면에 보기 좋게 표시되도록 한다.

트랙이 길어졌다는 이유로 일부분이 잘려 보이지 않도록 한다.

## 9. 트랙 자동 생성

게임 시작 전에는 트랙을 여러 번 생성할 수 있어야 한다.

기본 흐름은 다음과 같다.

1. 난이도 선택
2. 트랙 자동 생성
3. 트랙 미리보기
4. 마음에 들지 않으면 '트랙 다시 생성'
5. 원하는 트랙이 나오면 학습 시작

트랙 생성 알고리즘은 단순히 무작위 좌표를 연결하는 방식으로 구현하면 안 된다.

생성된 트랙이 실제로 주행 가능한지 확인해야 한다.

트랙의 폐회로 여부, 도로 폭, 교차 여부, 곡률, 체크포인트 배치 가능 여부 등을 검증한다.

유효하지 않은 트랙은 사용하지 않는다.

## 10. 트랙 시드

트랙은 재현 가능한 시드 기반 생성 방식을 사용한다.

사용자는 다음 기능을 사용할 수 있어야 한다.

- 현재 시드 확인
- 시드 복사
- 시드 직접 입력
- 시드로 트랙 생성

동일한 난이도, 시드, 생성 알고리즘 버전을 사용하면 동일한 트랙이 생성되어야 한다.

트랙 미리보기와 실제 충돌 판정은 동일한 트랙 데이터를 기반으로 동작해야 한다.

## 11. 트랙 고정

**가장 중요한 규칙 중 하나다.**

첫 세대의 주행이 시작되면 트랙은 고정된다.

그 이후에는 다음 기능을 사용할 수 없다.

- 트랙 다시 생성
- 난이도 변경
- 시드 변경
- 새로운 트랙으로 교체

1세대에서 100세대까지 진화하더라도 항상 동일한 트랙을 사용한다.

수동 진화와 자동 진화를 전환하더라도 트랙은 바뀌지 않는다.

자동 학습을 중단하고 다시 시작해도 트랙은 유지된다.

다른 트랙에서 실험하려면 새로운 판을 시작해야 한다.

'학습 초기화'는 현재 트랙을 유지하면서 유전자와 세대만 초기화하는 기능으로 구분한다.

# PART 4. 자동차 주행 시스템

## 12. 모든 자동차 동시 출발

한 세대의 모든 자동차는 반드시 동시에 출발한다.

예를 들어 자동차가 20대라면 20대 모두 같은 카운트다운 이후 출발한다.

자동차별로 순서대로 주행시키는 방식은 금지한다.

모든 자동차는 동일한 시뮬레이션 시간 기준으로 평가한다.

시작 위치는 공정성을 고려해 설계한다.

출발 위치에 차이가 있다면 진행률과 완주 기록에서 불공정한 이득이 발생하지 않도록 처리한다.

## 13. 자동차끼리 충돌하지 않음

자동차 간 충돌은 완전히 비활성화한다.

- 자동차가 서로 겹쳐도 충돌하지 않는다.
- 다른 자동차를 밀어내지 않는다.
- 다른 자동차 때문에 속도가 줄어들지 않는다.
- 거리 센서가 다른 자동차를 장애물로 인식하지 않는다.
- 이미 종료된 자동차도 다른 자동차의 주행을 방해하지 않는다.

자동차들은 동일한 트랙에서 서로 독립적으로 평가받는다.

## 14. 자동차 물리 엔진

자동차는 실제로 계산된 물리 상태에 따라 이동한다.

기본적으로 다음 상태를 관리한다.

- 위치 x, y
- 진행 방향
- 속도
- 조향각
- 가속 및 제동 명령
- 차체 충돌 영역
- 현재 진행률
- 주행 상태

2D kinematic bicycle model 또는 유사한 안정적인 자동차 운동학 모델을 권장한다.

물리 계산은 고정된 시간 간격으로 진행한다.

빠른 배속을 위해 자동차의 물리적 최대속도를 임의로 증가시키면 안 된다.

# PART 5. 자동차 주행 종료 조건

## 15. 정상 종료 조건

각 자동차는 다음 세 가지 조건 중 하나를 만족하면 주행을 종료한다.

### 조건 A. 트랙 벽 충돌

자동차 차체가 트랙의 벽 또는 도로 경계에 충돌하면 즉시 종료한다.

종료된 자동차는 해당 위치와 방향을 그대로 유지한다.

### 조건 B. 브레이크로 완전히 정지

자동차가 브레이크 명령으로 감속하여 속도가 0에 도달하면 종료한다.

단, 출발 직후 처음부터 속도가 0인 경우를 종료로 처리하면 안 된다.

일시정지 버튼을 눌렀다고 자동차가 브레이크 종료 판정을 받아서도 안 된다.

부동소수점 오차를 고려한 작은 속도 임계값을 사용할 수 있다.

### 조건 C. 한 바퀴 완주

자동차가 트랙을 한 바퀴 돌고 결승선을 정상적으로 통과하면 종료한다.

완주 판정에는 반드시 다음 조건을 적용한다.

1. 모든 체크포인트를 올바른 순서로 통과
2. 정상적인 방향으로 주행
3. 출발선에서 출발
4. 정확히 한 바퀴 주행
5. 결승선을 통과

결승선을 반복해서 앞뒤로 통과한다고 완주로 처리해서는 안 된다.

자동차가 지름길을 사용하거나 체크포인트를 생략해도 완주로 처리해서는 안 된다.

한 바퀴 완주 후에는 추가로 주행하지 않는다.

## 16. 주행 종료 후 처리

어떤 자동차가 먼저 종료하더라도 다른 자동차는 계속 주행한다.

종료된 자동차는 반드시 다음 상태를 유지한다.

- 종료 위치 고정
- 종료 방향 고정
- 실제 주행 종료 사유 기록
- 현재 세대 평가 결과 보존

모든 자동차가 종료할 때까지 동일한 화면에 남아 있어야 한다.

주행 종료된 자동차를 출발선으로 이동시키거나 한곳에 모아 정렬하지 않는다.

비정상적인 무한 주행이나 수치 오류를 방지하기 위한 안전 종료 조건은 별도로 둘 수 있다.

단, 안전 종료를 사용자가 지정한 세 가지 정상 종료 조건 중 하나인 것처럼 기록해서는 안 된다.

# PART 6. 자동차의 인공지능

## 17. 거리 센서

각 자동차는 트랙의 도로 경계까지의 거리를 감지하는 센서를 가진다.

초기 권장 센서 구조는 5개다.

- 정면
- 왼쪽 45도
- 오른쪽 45도
- 왼쪽 90도
- 오른쪽 90도

센서는 트랙 벽을 감지한다.

다른 자동차나 고스트 자동차는 감지하지 않는다.

센서값은 신경망 입력으로 사용한다.

필요하다면 선택한 자동차의 센서 방향과 측정 거리를 화면에 표시하는 기능을 추가할 수 있지만, 이는 핵심 기능 개발 이후의 선택적 확장이다.

## 18. 신경망

각 자동차에는 개별 신경망이 있다.

초기 권장 구조:

입력층 5개 → 은닉층 6개 → 출력층 2개

출력은 다음과 같다.

- 조향
- 가속 또는 제동

신경망의 가중치와 편향을 유전자로 취급한다.

예시 구조에서는 총 50개 파라미터가 된다.

각 자동차는 서로 다른 유전자를 가질 수 있어야 한다.

첫 세대는 무작위 초기 유전자를 사용한다.

신경망이 실제 주행 제어에 참여해야 하며, 자동차를 미리 설정된 경로로 움직이는 단순 애니메이션으로 만들어서는 안 된다.

# PART 7. 진행률과 순위 판정

## 19. 1등 선정 기준

**매 세대 1등 자동차는 트랙을 가장 멀리 진행한 자동차다.**

결승선 통과 여부가 1등의 필수 조건은 아니다.

예를 들어 다음과 같은 결과가 나왔다고 가정한다.

- 자동차 A: 35% 진행
- 자동차 B: 82% 진행
- 자동차 C: 64% 진행
- 자동차 D: 91% 진행

모든 자동차가 충돌하여 완주에 실패했더라도 D가 1등이다.

주행 종료 원인이 벽 충돌인지, 브레이크 정지인지는 진행률 비교보다 우선하지 않는다.

## 20. 완주 자동차의 순위

한 바퀴를 완주한 자동차는 진행률 100%로 처리한다.

여러 자동차가 100%를 달성했다면 완주 시간이 가장 짧은 자동차를 1등으로 선정한다.

미완주 자동차 사이에 유효 진행률이 같다면 해당 진행률에 먼저 도달한 자동차를 우선한다.

추가 동률은 일관된 기준으로 처리한다.

진행률은 단순히 차체가 결승선에 가까운지를 기준으로 측정하지 않는다.

반드시 체크포인트와 유효한 주행 방향을 반영해야 한다.

역주행, 체크포인트 건너뛰기, 트랙 바깥 지름길 등으로 진행률을 부풀리는 문제가 발생해서는 안 된다.

## 21. 적합도

유전 알고리즘의 적합도는 유효한 트랙 진행률을 가장 중요하게 평가한다.

보조 평가 요소로 다음을 사용할 수 있다.

- 주행 속도
- 완주 시간
- 안정성
- 충돌 여부
- 정지 여부
- 유효 진행 거리

단, 속도가 빠르다는 이유만으로 실제로 더 멀리 주행한 자동차가 불합리하게 낮게 평가되어서는 안 된다.

**금색 챔피언 선정에 사용하는 공식 1등 순위는 유효 진행률 우선 규칙을 따른다.**

# PART 8. 유전 알고리즘

## 22. 세대별 진화

각 세대의 모든 자동차가 주행을 완료하면 다음 작업을 수행한다.

1. 모든 자동차의 기록 및 적합도 평가
2. 우수 자동차 선정
3. 부모 유전자 선택
4. 엘리트 보존
5. 유전자 교차
6. 돌연변이
7. 다음 세대 생성
8. 다음 세대 모든 자동차 동시 출발

## 23. 기본 설정

초기 권장값:

- 자동차 개체 수: 20대
- 조절 범위: 약 10~100대
- 교차 확률: 약 80%
- 돌연변이 확률: 약 15%
- 엘리트 보존: 활성화

위 수치는 초기 제안값이며, 실제 실험 결과를 바탕으로 조절할 수 있어야 한다.

교차와 돌연변이는 반드시 실제 신경망 유전자에 적용한다.

세대가 바뀌었다는 이유로 적합도만 임의로 높이는 구현은 금지한다.

# PART 9. 이전 세대 1등 금색 챔피언

## 24. 금색 챔피언의 정의

이전 세대에서 유효 진행률 기준 1등을 차지한 자동차를 다음 세대에 엘리트 개체로 보존한다.

해당 자동차의 유전자는 교차나 돌연변이를 적용하지 않고 그대로 복제한다.

이렇게 보존된 자동차 **1대만** 금색 챔피언으로 표시한다.

### 예시

1세대에서 7번 자동차가 가장 멀리 주행했다면:

2세대에는 7번 자동차의 유전자를 그대로 가진 엘리트 자동차가 등장한다.

해당 엘리트 자동차는 금색으로 강조된다.

3세대에서는 2세대의 새로운 1등 자동차가 다음 세대 챔피언의 기준이 된다.

이 과정을 반복한다.

**1세대에는 이전 세대 1등이 존재하지 않으므로 금색 자동차가 없다.**

## 25. 금색 오라

금색 챔피언 자동차는 주행하는 동안 **금색 오라를 발산하며 이동**해야 한다.

단순히 금색 테두리만 표시하는 것보다 눈에 띄는 효과를 사용한다.

권장 효과:

- 금색 차체 강조
- 부드러운 외곽 광원
- 주변으로 퍼지는 빛
- 작은 금색 파티클
- 주행 중 은은한 반짝임

자동차 자체는 단순한 형태를 유지한다.

너무 화려하거나 복잡한 스포츠카로 만들지 않는다.

금색 오라가 실제 차량 위치나 충돌 크기를 바꾸어서는 안 된다.

주행을 종료한 경우에는 오라 애니메이션을 멈추고 금색 강조를 유지할 수 있다.

## 26. 챔피언의 중요한 구분

금색 자동차는 실제로 주행하는 자동차다.

정상적으로 센서를 사용하고 신경망으로 운전하며 충돌 및 완주 판정을 받는다.

반면 고스트 자동차는 과거 주행 기록을 재생하는 시각적 객체다.

두 기능을 혼동하지 않는다.

또한 이전 챔피언의 유전자를 일부 물려받은 일반 자손까지 모두 금색으로 만들지 않는다.

# PART 10. 수동 진화 모드

## 27. 수동 모드의 기본 흐름

수동 모드에서는 사용자가 직접 다음 세대의 부모 자동차를 선택한다.

한 세대의 모든 자동차가 주행을 종료하면 부모 선택 단계로 진입한다.

**이때 중앙의 기존 트랙 화면을 그대로 유지해야 한다.**

자동차를 이동시키거나 새로운 결과 화면을 만들지 않는다.

## 28. 자동차 선택 방법

다음 두 가지 선택 방식을 지원한다.

### 클릭 선택

자동차를 클릭하면 해당 자동차가 선택된다.

다시 클릭하면 선택이 해제된다.

### 드래그 선택

마우스로 직사각형 영역을 드래그하면 해당 영역에 포함된 자동차들을 한꺼번에 선택한다.

선택은 기존 선택에 추가되는 방식으로 한다.

자동차가 서로 겹쳐 있는 경우에도 드래그 영역 안에 포함된 자동차는 모두 선택할 수 있어야 한다.

겹친 자동차를 선택하기 위해 별도의 확대 화면이나 팝업을 만들 필요는 없다.

사용자는 드래그 선택이 가능하면 충분하다고 확정했다.

## 29. 선택 상태 표시

선택된 자동차에는 명확한 테두리를 표시한다.

금색 챔피언의 오라와 구분되는 색상이나 형태를 사용한다.

다음 정보를 제공한다.

- 현재 선택된 자동차 수
- 선택된 자동차 강조
- 선택 초기화

## 30. 결정완료 버튼

**가장 중요한 수동 모드 규칙이다.**

자동차를 클릭하거나 드래그하는 동작만으로 다음 세대로 넘어가서는 안 된다.

사용자가 부모 자동차를 모두 선택한 뒤 별도로 **'결정완료' 버튼**을 눌러야 한다.

결정완료를 눌렀을 때만 부모 선택을 확정하고 다음 세대 유전자를 생성한다.

부모 자동차는 기본적으로 최소 2대가 필요하도록 설계한다.

최대 부모 수는 기존에 확정된 엄격한 제한이 없으므로 임의로 5대로 고정하지 않는다.

## 31. 부모 선택 이후

결정완료 버튼을 누르면 다음 작업을 수행한다.

- 선택된 부모 유전자 확보
- 이전 세대 1등 엘리트 보존
- 교차 및 돌연변이
- 다음 세대 개체군 생성
- 세대 번호 증가
- 다음 세대 동시 출발

수동 모드에서도 엘리트 보존 규칙은 유지한다.

사용자가 이전 세대 1등을 부모로 선택하지 않았더라도, 엘리트 1대는 별도로 보존한다.

# PART 11. 완전 자동 진화 모드

## 32. 자동 진화의 핵심 목적

**자동 진화는 Race Simulator의 핵심 실행 모드다.**

단순히 부모 자동차만 자동 선택하는 기능이 아니다.

자동차의 출발부터 다음 세대 생성까지 모든 과정을 사용자의 추가 입력 없이 자동으로 수행해야 한다.

## 33. 자동 학습 시작

사용자가 일반 화면에서 **'자동 학습 시작'** 버튼을 누르면 완전 자동 진화가 실행된다.

동작 순서:

1. 모든 자동차 동시 출발
2. 실제 물리 계산으로 주행
3. 자동차별 종료 조건 판정
4. 모든 자동차의 주행 완료
5. 실제 진행률과 적합도 평가
6. 우수 부모 자동차 자동 선택
7. 엘리트 1대 보존
8. 유전자 교차
9. 돌연변이
10. 다음 세대 생성
11. 세대 번호 증가
12. 모든 자동차 동시 출발

이 과정을 사용자가 정지 버튼을 누를 때까지 반복한다.

자동 모드에서는 부모 선택을 확인하는 팝업이나 결정완료 버튼 입력이 필요하지 않다.

## 34. 자동 모드의 빠른 배속

자동 진화는 매우 높은 배속으로 진행할 수 있어야 한다.

그러나 계산 결과를 생략해서는 안 된다.

빠른 학습을 위해 실제 물리 계산을 짧은 시간에 많이 수행한다.

자동차의 최대속도를 임의로 높이거나 물리 법칙을 바꾸지 않는다.

고속 계산 중에도 다음 요소가 화면에 표시되어야 한다.

- 실제로 움직이는 자동차
- 현재 세대 번호
- 주행 상태
- 세대별 통계
- 적합도 그래프
- 완주 기록
- 금색 챔피언
- 설정된 고스트

사용자가 화면을 보고 실제로 세대가 진화하고 있다는 것을 확인할 수 있어야 한다.

애니메이션과 계산을 분리하여 계산은 빠르게 수행하되 화면은 지속적으로 갱신한다.

필요하면 Web Worker를 사용한다.

브라우저가 멈추거나 정지 버튼을 누를 수 없는 문제가 발생해서는 안 된다.

## 35. 자동 학습 정지

사용자가 **'자동 학습 정지'** 버튼을 누르면 자동 진화를 중단한다.

다만 이 버튼은 학습 초기화 버튼이 아니다.

다음 사항을 반드시 지킨다.

1. 자동 세대 반복 중단
2. 진행 중인 계산을 안전한 지점에서 일시정지
3. 기존 일반 시뮬레이션 화면으로 즉시 복귀
4. 현재 트랙 유지
5. 현재 세대 유지
6. 자동차 유전자 유지
7. 자동차 현재 위치 유지
8. 자동차 속도와 주행 상태 유지
9. 이전 세대 학습 기록 유지
10. 적합도 그래프 및 통계 유지

**정지 후 별도의 선택창을 만들지 않는다.**

특히 다음과 같은 화면은 절대로 만들지 않는다.

- 수동으로 이어하기 / 자동으로 이어하기 선택창
- 별도 모드 선택 페이지
- 정지 후 확인 팝업
- 독립된 자동 학습 종료 화면

자동 학습 정지를 누르면 **원래 일반 화면으로 바로 돌아가야 한다.**

일반 화면에 이미 수동 조작과 자동 학습 버튼이 존재하기 때문이다.

사용자는 그 화면에서 다음에 무엇을 할지 직접 결정한다.

## 36. 자동 학습 정지 이후

예를 들어 24세대 주행 중 자동 학습을 정지했다면:

- 24세대 그대로 유지
- 자동차들의 현재 위치 유지
- 자동차 유전자 유지
- 이전 세대 기록 유지
- 진행 중인 시뮬레이션 일시정지

사용자가 일반 주행을 재개하면 24세대의 남은 주행을 계속 진행할 수 있어야 한다.

이후 자동차들이 모두 종료되면 직접 부모를 선택할 수 있다.

다시 자동 학습을 시작하면 중단된 24세대에서 자동으로 이어서 진행할 수 있어야 한다.

자동 모드를 중단했다는 이유로 새 세대를 생성하거나 기존 세대를 초기화하면 안 된다.

# PART 12. 배속, 일시정지 및 건너뛰기

## 37. 일반 주행 배속

일반 화면에서는 다음 배속을 지원한다.

- 1배속
- 2배속
- 5배속
- 10배속

필요하다면 자동 학습에서 이보다 높은 배속을 사용할 수 있다.

배속은 시뮬레이션 계산 속도를 변경하는 기능이다.

자동차의 물리적 성능 자체를 바꾸는 기능이 아니다.

## 38. 일시정지 및 재개

일시정지하면 현재 자동차 위치와 상태를 보존한다.

재개하면 동일한 상태에서 물리 계산을 계속한다.

## 39. 건너뛰기

**건너뛰기는 자동차의 주행을 강제로 종료하는 기능이 아니다.**

현재 세대의 남은 주행을 빠르게 계산하여 평가를 완료하는 기능이다.

화면 렌더링은 생략할 수 있지만 센서 계산, 신경망 판단, 물리 계산, 충돌 판정, 완주 판정은 정상적으로 수행해야 한다.

수동 모드에서 건너뛰기를 완료하면 정상적인 부모 선택 단계로 진입한다.

자동 모드에서는 기존 자동 진화 규칙에 따라 진행한다.

# PART 13. 완주 기록 표시

## 40. 오른쪽 상단 완주 기록

중앙 시뮬레이션 화면의 오른쪽 상단에 해당 세대 최고 완주 기록을 표시한다.

표시 규칙:

### 아직 완주 자동차가 없는 경우

`--:--.--`

### 첫 자동차가 완주한 경우

해당 자동차의 실제 완주 시간을 표시한다.

### 이후 더 빠른 자동차가 완주한 경우

더 빠른 완주 시간으로 갱신한다.

### 해당 세대에 완주 자동차가 없는 경우

`완주 기록 없음`

완주 시간이 기록된 자동차 번호도 함께 표시할 수 있다.

완주 시간은 실제 시계 시간이 아니라 시뮬레이션 내부 시간을 사용한다.

1배속, 10배속, 자동 학습, 건너뛰기 여부와 관계없이 같은 주행은 같은 완주 시간이 기록되어야 한다.

# PART 14. 고스트 자동차 비교

## 41. 고스트 기능의 목적

과거 세대의 우수 자동차가 실제로 어떻게 주행했는지 현재 세대와 비교하기 위한 기능이다.

## 42. 고스트의 동작

이전 자동차의 실제 주행 데이터를 기록한다.

이후 해당 기록을 반투명 자동차 형태로 현재 트랙 위에 재생한다.

고스트는 과거의 위치, 방향, 속도 기록을 따라 움직인다.

현재 세대의 실제 자동차들과 같은 시뮬레이션 시간을 기준으로 재생한다.

## 43. 고스트 비교 대상

다음 방식을 지원한다.

- 이전 세대 1등 자동차
- 역대 최고 자동차
- 특정 세대 1등 자동차

기본적으로 역대 최고 자동차를 표시하는 방식을 권장한다.

고스트의 1등 기록도 유효 진행률 우선 기준을 사용한다.

## 44. 고스트의 절대 조건

고스트는 시각적인 비교 객체일 뿐이다.

다음 기능에 영향을 주면 안 된다.

- 자동차 물리
- 충돌 판정
- 거리 센서
- 적합도
- 개체 수
- 부모 선택
- 유전자 진화

고스트를 켜거나 꺼도 실제 자동차들의 학습 결과는 동일해야 한다.

고스트는 수동 부모 선택 대상에 포함되지 않는다.

수동 부모 선택 단계에서는 기본적으로 고스트를 숨긴다.

# PART 15. 실험 저장 및 불러오기

## 45. 실험 저장

사용자가 진행한 진화 실험을 파일로 저장할 수 있어야 한다.

단순히 통계만 저장하는 기능이 아니다.

실제 유전자와 진화 상태까지 저장해야 한다.

저장할 데이터:

- 실험 이름
- 저장 시점
- 트랙 시드
- 트랙 난이도
- 트랙 실제 좌표
- 출발선 및 체크포인트
- 현재 세대
- 유전 알고리즘 설정
- 자동차 개체 수
- 각 자동차 유전자
- 적합도
- 진행률
- 종료 사유
- 부모 선택 기록
- 세대별 학습 결과
- 고스트 기록
- 현재 시뮬레이션 상태
- 파일 형식 버전
- 재현에 필요한 난수 상태

기본 파일 형식은 JSON으로 한다.

## 46. 실험 불러오기

저장된 JSON 파일을 선택하면 해당 실험을 복원한다.

예를 들어 50세대까지 학습한 실험을 저장했다면 이후 불러와 51세대부터 계속 학습할 수 있어야 한다.

불러오기 시 다음 정보가 유지되어야 한다.

- 트랙
- 자동차 유전자
- 세대 번호
- 진화 기록
- 그래프
- 학습 설정
- 고스트 기록

실험을 불러온 뒤 트랙이 다른 형태로 바뀌어서는 안 된다.

## 47. 수동 부모 선택 중 저장

수동 선택 단계에서도 다음 정보를 보존한다.

- 종료된 자동차 위치
- 자동차 방향
- 선택된 부모 자동차
- 결정완료 여부

결정완료를 누르지 않은 상태로 저장했다면 불러온 뒤에도 자동으로 다음 세대로 넘어가면 안 된다.

## 48. 학습 중 저장

주행 도중 정확한 중간 상태를 저장하는 기능은 복잡할 수 있다.

초기 버전에서는 안전한 세대 경계의 저장을 우선 구현할 수 있다.

단, 저장된 상태가 어느 시점인지 사용자에게 명확히 안내해야 한다.

반면 자동 학습 정지 기능은 실행 중인 현재 상태를 메모리에서 그대로 보존해야 한다.

## 49. 결과 내보내기

세대별 통계를 CSV로 내보낼 수 있어야 한다.

다음 정보들을 포함한다.

- 세대 번호
- 최고 적합도
- 평균 적합도
- 최고 진행률
- 평균 진행률
- 완주 자동차 수
- 충돌 자동차 수
- 브레이크 정지 자동차 수
- 최고 완주 시간
- 해당 세대 1등 자동차

필요하면 최고 자동차의 유전자도 별도로 저장할 수 있도록 한다.

# PART 16. 상태 관리

## 50. 시뮬레이션 상태

명확한 상태 관리 구조를 사용한다.

대표적인 상태:

- 트랙 선택
- 주행 준비
- 출발 카운트다운
- 주행 중
- 일시정지
- 세대 평가 완료
- 수동 부모 선택
- 자동 진화 실행

각 상태에서 가능한 조작을 명확하게 제한한다.

예를 들어 자동차가 주행 중일 때 수동 부모 선택이 가능해서는 안 된다.

트랙이 이미 확정되었다면 시드를 변경할 수 없어야 한다.

자동 학습 중단과 전체 학습 초기화는 명확히 다른 기능으로 분리한다.

자동 진화 여부는 일반 화면 상태와 별도로 관리하는 것을 권장한다.

**components:** 한국어 UI와 버튼 및 설정 패널

**persistence:** JSON 저장·복원 및 CSV 내보내기

## 62. 진행률 계산 문제

헤어핀이나 S자 곡선에서 차가 다른 구간과 가까워졌다는 이유로 진행률이 갑자기 증가해서는 안 된다.

체크포인트 및 경로 연속성을 고려해 실제 유효한 진행률을 계산한다.

실제 주행 결과는 렌더링 주사율에 의존해서는 안 된다.

60FPS와 30FPS에서 같은 유전자가 다른 결과를 만들어서는 안 된다.

자동 학습 배속이 높아져도 물리 계산의 의미는 유지해야 한다.

## 64. 중복 세대 생성

자동 학습 중지, 건너뛰기, 부모 선택 확정 등의 동작이 겹쳐 한 세대가 두 번 생성되는 문제를 방지한다.

## 65. 트랙 고정

React 상태 변경이나 화면 갱신 때문에 트랙이 새로 생성되는 문제가 발생해서는 안 된다.

현재 판의 트랙은 명시적으로 새 판을 시작하기 전까지 유지한다.

## 66. 사용자 경험

수동 선택을 위한 별도 화면이나 자동 학습 정지 후 모드 선택 화면을 임의로 추가하지 않는다.

사용자가 확정한 UI 동작 방식을 그대로 구현한다.

# PART 25. 가장 중요한 최종 요구사항 요약

Race Simulator는 다음 핵심 원칙을 반드시 만족해야 한다.

**1. 트랙은 하나의 길로만 이루어진 폐회로다.**

갈림길, 지름길, 함정, 교차로는 절대 없다.

**2. 모든 자동차는 동시에 출발한다.**

자동차끼리는 서로 충돌하거나 방해하지 않는다.

**3. 자동차는 세 가지 조건으로 주행을 종료한다.**

벽 충돌, 브레이크 완전 정지, 한 바퀴 완주.

**4. 1등은 유효 진행률로 결정한다.**

완주하지 못해도 가장 멀리 주행했다면 1등이다.

**5. 이전 세대 1등은 다음 세대에 금색 챔피언으로 등장한다.**

유전자를 그대로 보존한 실제 자동차 1대이며, 주행 중 금색 오라를 발산한다.

**6. 수동 진화에서는 원래 트랙에서 자동차를 직접 선택한다.**

클릭 및 드래그로 부모를 고르고, 결정완료 버튼을 눌러야만 다음 세대로 넘어간다.

**7. 자동 진화에서는 모든 과정이 자동 반복된다.**

실제 자동차 주행, 평가, 부모 선택, 교차, 돌연변이, 다음 세대 출발을 정지 버튼 전까지 반복한다.

**8. 자동 학습 정지는 원래 일반 화면으로 바로 복귀한다.**

별도의 선택창이나 팝업은 만들지 않는다. 기존 학습 데이터는 모두 보존한다.

**9. 고스트 자동차는 이전 기록을 보여주는 비교 대상이다.**

실제 자동차의 물리 계산이나 학습에 영향을 주지 않는다.

**10. 실험을 저장하고 불러올 수 있어야 한다.**

트랙, 유전자, 세대, 통계를 저장하여 나중에 이어서 학습할 수 있어야 한다.

# 최종 요청

위의 전체 인수인계서를 Race Simulator 프로젝트의 개발 기준으로 삼아라.

먼저 요구사항을 기능별로 분석하고, 충돌하는 조건이 있는지 확인하며, 실제 구현 가능한 아키텍처와 개발 순서를 제안해라.

이미 만들어진 프로젝트가 있다면 현재 구현 상태를 실제 파일과 실행 결과를 근거로 점검해라.
