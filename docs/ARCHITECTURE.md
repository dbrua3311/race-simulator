# 아키텍처

요구사항 원문은 `HANDOFF_FOR_CLAUDE.md`. 이 문서는 그것을 어떻게 구현할지에 대한 설계다.
아직 코드가 없으므로 여기 적힌 것은 **계획**이며, 구현되면 해당 절에 "구현됨"을 표시한다.

## 1. 큰 그림

```
┌──────────────────────── 메인 스레드 (React) ────────────────────────┐
│  components/  왼쪽 패널 · 오른쪽 통계 · 그래프(Recharts)             │
│  visualization/  Canvas 렌더러 (트랙, 자동차, 금색 오라, 고스트,     │
│                  선택 테두리, 드래그 사각형)                         │
│  app/  UI 상태 스토어, 워커와의 메시지 송수신                        │
└───────────────▲─────────────────────────────┬───────────────────────┘
                │ 스냅샷(위치·방향·상태, 통계)  │ 명령(시작/일시정지/배속/
                │  ~60Hz                        │  건너뛰기/자동학습/결정완료…)
┌───────────────┴──────────── Web Worker ─────▼───────────────────────┐
│  workers/  시뮬레이션 루프 (고정 dt, 시간 예산 단위로 끊어 실행)      │
│  ─────────── 아래는 DOM 을 모르는 순수 TypeScript 코어 ───────────── │
│  tracks/      트랙 생성·검증·진행률                                  │
│  simulation/  물리 · 센서 · 벽 충돌 · 종료 판정 · 완주 판정           │
│  genetics/    신경망 · 유전자 · 선택 · 교차 · 돌연변이 · 엘리트      │
│  core/rng     시드 기반 난수 (상태 직렬화 가능)                      │
└─────────────────────────────────────────────────────────────────────┘
persistence/  JSON 저장·복원(검증 후 교체), CSV 내보내기 — 코어 상태를 직렬화
```

핵심 원칙 세 가지:

1. **시뮬레이션 코어는 순수 함수/순수 데이터다.** DOM, React, `Date.now()`, `Math.random()` 을 쓰지 않는다.
   그래서 Vitest 로 브라우저 없이 검증할 수 있고, 워커와 테스트가 같은 코드를 쓴다.
2. **시뮬레이션 상태는 JSON 으로 그대로 직렬화 가능한 평범한 객체다.** 저장·불러오기·자동 학습 정지 후 보존이 같은 구조로 해결된다.
3. **권위 있는 상태는 워커 하나에만 있다.** 메인 스레드는 스냅샷을 그리기만 한다. 세대 생성은 워커 안의 단일 함수에서만 일어난다.

## 2. 결정론(재현성)

- 물리는 고정 시간 간격 `DT = 1/60 s` 로만 진행한다. 렌더링 FPS 와 무관하다.
- 배속 = "실제 1초에 몇 스텝을 계산하느냐"만 바꾼다. `DT`, 최고속도, 가속도는 그대로다.
  → 1배속·10배속·건너뛰기·자동 학습에서 같은 유전자는 같은 완주 시간이 나온다 (요구 37, 40, 63).
- 완주 시간 = `완주 스텝 수 × DT` (시뮬레이션 내부 시간).
- 난수는 시드 기반 PRNG(sfc32 등) 하나를 쓰고, 그 상태(4개 정수)를 저장 파일에 넣는다.
  트랙 생성용 난수와 진화용 난수는 서로 다른 스트림으로 분리한다.
- 자동차끼리 상호작용이 없으므로 각 자동차의 주행은 자기 유전자와 트랙만으로 결정된다.
  → **같은 유전자를 같은 출발 자리에 두면 정확히 같은 주행을 반복한다.**
- 금색 챔피언은 직전 세대 1등이 출발했던 자리에 그대로 서고, 나머지 차만 남은 자리에 무작위 배치한다 (`DECISIONS.md` D1).
  그래서 챔피언은 직전 1등 주행을 정확히 재현하며, 이것이 결정론을 확인하는 자동 테스트가 된다.
- 출발 자리 배치도 진화용 시드 PRNG 로 뽑으므로 같은 실험은 같은 배치로 재현된다.
- 주의: `Math.sin/cos/tanh` 결과는 브라우저 엔진마다 마지막 자리가 다를 수 있다. 같은 브라우저에서는 재현된다.
  다른 브라우저에서 저장 파일을 열면 주행이 미세하게 달라질 수 있음을 문서화한다.

## 3. 상태 기계

일반 화면 상태(`phase`)와 자동 진화 여부(`autoEvolution: boolean`)를 분리한다 (요구 50).

| phase | 의미 | 가능한 조작 |
|---|---|---|
| `trackSetup` | 난이도·시드 선택, 미리보기 | 트랙 생성/다시 생성, 시드 입력, 개체 수 설정, 주행 시작 |
| `ready` | 세대 생성됨, 출발 전 | 주행 시작, 자동 학습 시작, 저장 |
| `countdown` | 출발 카운트다운 (실시간, 시뮬 시간 0 유지) | 일시정지 |
| `running` | 주행 중 | 일시정지, 배속, 건너뛰기, 자동 학습 시작/정지 |
| `paused` | 일시정지 | 재개, 배속, 건너뛰기, 자동 학습 시작, 저장 |
| `evaluated` | 모든 차 종료, 평가 완료 (일시적) | — |
| `parentSelection` | 수동 부모 선택 | 클릭/드래그 선택, 선택 초기화, 결정완료, 자동 학습 시작, 저장 |

- `trackLocked` 는 1세대 주행이 처음 시작되는 순간 `true` 가 되고, "새 판 시작" 외에는 되돌리지 않는다.
- 자동 학습 정지 = `autoEvolution = false` + 주행 중이면 `paused`. 세대 경계에 있었다면 `parentSelection`.
  선택창·팝업 없음 (요구 35).
- "학습 초기화" (트랙 유지, 유전자·세대 초기화)와 "새 판 시작" (트랙까지 새로)은 별도 버튼.

## 4. 트랙 (`src/tracks`)

**생성 (구현됨, `src/tracks/generate.ts`):** 중심선을 극좌표 r(θ) 로 정의한다.
- 각도마다 점이 정확히 하나 → 자기 교차·갈림길·되돌아가는 길이 **구조적으로 불가능**하다.
- r(θ) = 기준 반지름(215 m) × (1 + 무작위 푸리에 성분 합). 난이도가 높을수록 고차 성분이 많고 진폭이 커서 급커브·S자가 많다.
- 아래쪽은 기준 원의 현(chord)인 정확한 직선(메인 직선 130 m, 출발선 뒤 105 m = 출발 그리드). 직선 끝과 곡선은 값·기울기·2차 도함수를 맞춘 5차 에르미트 보간으로 이어 곡률이 연속이다.
- 너무 급하면 버리지 않고 굴곡 배율을 이진 탐색으로 줄여, 난이도가 허용하는 가장 급한 모양을 쓴다.
- 4000점으로 그린 뒤 2 m 간격으로 다시 샘플링. 출발선이 0번 점.

**검증 (`src/tracks/validate.ts`, 하나라도 실패하면 같은 난수열로 다음 후보 — 결정론적 재시도):**
1. 한 바퀴 길이가 난이도 범위 안
2. 가로세로 비율 0.65~1.6 (화면에 잘리지 않게)
3. 최소 곡률 반지름 ≥ 난이도 기준 (하 30 m / 중 18 m / 상 14 m) — 안쪽 벽이 접히지 않음
4. 급커브 수·좌우 전환 수가 난이도에 맞음
5. 경로상 충분히 떨어진 두 지점은 **도로 폭 + 벽 간격 8 m 이상** 떨어짐 — 도로끼리 맞닿아 지름길이 생기는 구조 차단
6. 중심선, 좌·우 벽의 자기 교차 및 좌·우 벽 사이 교차 없음 (닿기만 해도 실패)

결과: 난이도마다 시드 1000개씩 모두 통과 (`TRACK_SEEDS=1000 npm test`). 한 바퀴 약 1.3~1.9 km. 생성 시간은 트랙당 하 약 17 ms, 중 약 35 ms, 상 약 70 ms.

트랙 데이터 = 중심선 점열 + 누적 거리 + 좌/우 벽 선분 + 출발선 + 체크포인트 + `{난이도, 시드, 생성기버전}`.
미리보기, 충돌, 센서, 진행률이 **모두 이 하나의 데이터**를 쓴다. 저장 시 좌표를 그대로 넣고, 불러올 때 재생성하지 않는다.

**진행률 (구현됨, `src/simulation/progress.ts`):** 자동차마다 "현재 중심선 구간 인덱스"를 들고 있고, 매 스텝 **이전 인덱스 주변 창(window) 안에서만** 가장 가까운 구간을 찾는다.
헤어핀에서 옆 구간이 가까워져도 인덱스가 건너뛰지 않는다 (요구 62).
누적 진행 거리는 **각 차의 출발 위치 기준** 언랩된 값(뒤로 가면 음수 가능)이고, 체크포인트는 그 차의 출발점부터 순서대로만 통과 처리한다.
유효 진행률 = 순서대로 통과한 체크포인트와 연속 경로를 만족하는 최대 진행 거리 / 한 바퀴 길이.
완주 = 모든 체크포인트 순서 통과 + 누적 진행 ≥ 한 바퀴 (정방향으로 자기 출발점 통과).
출발 그리드에서 앞뒤 자리가 달라도 모든 차가 같은 거리를 달려야 하므로 공정하다 (`DECISIONS.md` D1).

## 5. 시뮬레이션 (`src/simulation`) — 3단계에서 물리·벽 충돌·동시 출발 구현

- **물리 (구현됨, `physics.ts`):** 운동학 자전거 모델(차체 중심 기준). 차 5.0 m × 2.2 m, 축거 3 m, 최대 조향 0.6 rad(조향 속도 2.5 rad/s), 최고 30 m/s, 가속 6 / 제동 14 m/s², 공기 저항. 상태 `x, y, heading, speed, steer`. 출력1 → 목표 조향각(조향 속도 제한), 출력2 → 양수 가속 / 음수 제동.
  후진 없음 (`speed ≥ 0`). 최고속도는 상수이며 배속과 무관.
- **차체:** 회전 사각형(OBB). 화면에 그리는 크기 = 충돌 크기.
- **벽 충돌 (구현됨, `collision.ts`):** 차체 네 꼭짓점 중 하나라도 중심선(현재 위치 주변 선분)에서 도로 폭/2 보다 멀면 충돌. 현재 위치는 이전 인덱스 ±10 점 안에서만 다시 찾는다(옆 구간으로 건너뛰지 않음).
- **센서 (구현됨, `sensors.ts`):** 0°, ±45°, ±90° 광선 5개, 차 중심에서 최대 80 m. 벽 선분에만 교차 (다른 차·고스트 무시). 벽 선분을 8 m 격자에 담고 광선이 지나는 칸만 검사(DDA). 0~1 로 정규화해 신경망 입력.
- **종료 사유 (정상, 구현됨):** `wall`(벽 충돌), `brake`(제동 명령 중 속도 ≤ 0.05 m/s, 단 한 번이라도 0.5 m/s 이상 달린 뒤에만), `finish`(완주). 같은 스텝에 겹치면 벽 → 완주 → 브레이크 순.
- **종료 사유 (안전, 별도 표기, 구현됨):** `noProgress`(5초 동안 유효 진행 1 m 미만 — 출발부터 가속하지 않는 차, 역주행, 제자리 정체), `timeLimit`(세대 최대 300 s), `numeric`(NaN 등).
  통계와 CSV 에서 정상 3종과 구분해 집계한다 (요구 16).
- 종료된 차는 위치·방향을 그대로 고정하고 이후 계산에서 빠진다.
- **한 세대 (구현됨, `world.ts`):** 그리드 자리에 무작위 배치 → 같은 스텝에 동시 출발. 차끼리는 어떤 계산에서도 서로를 참조하지 않는다(혼자 달려도 50대 속에서 달려도 같은 결과 — 테스트로 확인).
- 조종은 각 차의 신경망(센서 5개 → 조향·가속/제동). 테스트에서는 조종기를 바꿔 끼울 수 있다(예: 중심선 추종 모범 운전자로 완주 판정 검증).
- 계산 속도: 50대 모두 달릴 때 실시간의 약 60배, 100대 약 36배 (한 스레드).

## 6. 유전 알고리즘 (`src/genetics`) — 구현됨 (5단계)

- **신경망 (구현됨, `network.ts`):** 5 → 6(tanh) → 2(tanh). 파라미터 50개 = 유전자 `number[]`(JSON 저장 가능). 구조는 `genetics/params.ts` 설정값. 출력 1 = 조향, 출력 2 = 가속(+)/제동(−). 1세대는 [-1, 1] 균등 난수.
- **공식 순위 (금색 챔피언·1등·고스트 기준):**
  1. 유효 진행률 높은 순 (완주 = 100%)
  2. 둘 다 완주면 완주 시간 짧은 순
  3. 미완주 동률이면 그 진행률에 먼저 도달한 순
  4. 그래도 같으면 자동차 번호 작은 순
- **적합도:** 공식 순위와 순서가 어긋나지 않게 설계한다. 예: 미완주 `진행률 × 100`, 완주 `100 + 시간 보너스`.
  → 더 멀리 간 차가 속도 때문에 낮게 평가되는 일이 없다 (요구 21).
- **엘리트:** 직전 세대 공식 1등 1대를 복제(교차·돌연변이 없음) → 금색 챔피언. 1세대에는 없음.
  챔피언은 직전 세대에 출발했던 그리드 자리를 물려받는다.
- **자동 부모 선택:** 토너먼트 선택 (k=3). **수동:** 사용자가 고른 부모 집합(≥2대) 안에서 무작위로 짝을 짓는다.
- **교차:** 확률 pc 로 뉴런 단위 균등 교차 (한 뉴런의 가중치·편향을 묶어서 상속), 아니면 부모 복제. 가능하면 서로 다른 두 부모.
- **돌연변이:** 유전자마다 확률 pm(기본 15%) 으로 정규분포 노이즈(표준편차 0.5)를 더한다.
- **세대 생성 함수는 하나뿐**: `nextGeneration(experiment, parentIds, expectedGeneration)` (`src/simulation/experiment.ts`).
  `expectedGeneration` 이 현재 세대와 다르면 거부 → 결정완료 두 번 클릭, 정지·건너뛰기 겹침으로 인한 중복 생성 차단 (요구 64).

## 6-1. 실험 (`src/simulation/experiment.ts`) — 구현됨

실험 = 트랙 + 설정 + 현재 세대 주행(World) + 진화용 난수 상태 + 세대별 기록 + 고스트. 평범한 데이터라 그대로 저장된다.
워커가 실험의 주인이고, 화면은 스냅샷과 "세대 평가 완료" 이벤트로 따라간다.
- 세대가 끝나면 `evaluate` → 기록·1등 궤적(고스트) 저장
- 수동: 부모 선택 대기 → 결정완료(`confirmParents`) / 자동 선택 모드: 바로 다음 세대가 그리드에 선다 / 자동 학습: 다음 세대 즉시 출발
- 금색 챔피언 = 다음 세대의 0번(화면 번호 1번), 직전 1등이 출발했던 자리

## 7. 워커 루프 (`src/workers`) — 구현됨 (`simLoop.ts`)

- 워커는 "시간 예산(약 8ms) 만큼 스텝 계산 → 메시지 처리 기회 양보 → 반복" 구조로 돈다.
  그래서 고속 자동 학습 중에도 정지 명령이 바로 처리되고 브라우저가 멈추지 않는다 (요구 34, 61).
- 일반 배속: 실제 경과 시간 × 60 × 배속 만큼 스텝 (누적기 사용).
- 자동 학습 고속: 예산(10 ms)이 허용하는 만큼 최대한 계산하고 양보, 세대가 바뀌어도 이어서 계산. 실제 달성 배속을 화면에 표시.
- 자동 학습 정지: 자동 반복만 끄고, 주행 중이면 그 자리에서 일시정지. 세대·위치·속도·기록 그대로 (선택창 없음).
- 건너뛰기: 남은 주행을 렌더링 없이 계산(같은 스텝 함수), 끝나면 평가 단계로.
- 스냅샷은 약 60Hz 로 전송 (위치·방향·상태를 `Float32Array` 로 묶어 transfer).
- 메인 스레드는 결과를 그리기만 하므로 렌더 FPS 가 물리 결과에 영향을 줄 수 없다 (요구 63).

## 8. 렌더링 (`src/visualization`)

- 트랙은 크기가 바뀔 때만 오프스크린 캔버스에 한 번 그리고 매 프레임 복사.
- 월드 좌표(m) → 화면 좌표 변환 하나로 트랙 전체가 중앙 영역에 맞게 들어오도록 한다.
- 자동차: 단순 탑다운 실루엣 + 앞쪽 표시(방향) + 번호. 개체별 구분 색 (HSL 균등 분할).
- 금색 챔피언: 금색 차체 + 방사형 그라디언트 광원 + 작은 파티클 (파티클은 순수 시각 효과, 물리와 무관).
- 선택: 금색과 구분되는 청록색 테두리. 클릭 판정은 차체보다 넓은 최소 반경 (작은 차도 잘 클릭되게).
- 드래그 선택: 사각형 안에 중심이 들어온 모든 차를 기존 선택에 추가. 겹친 차도 모두 선택.
- 고스트: 반투명. 부모 선택 단계에서는 기본으로 숨김. 클릭 판정 대상 아님.

## 9. 고스트

- 세대마다 공식 1등의 궤적(시뮬 시간, x, y, heading, speed)을 10~20Hz 로 다운샘플해 기록.
- 재생은 현재 시뮬 시간에 맞춰 보간. 물리·센서·적합도와 완전히 분리된 읽기 전용 데이터.
- 대상: 직전 세대 1등 / 역대 최고(기본) / 특정 세대 1등.

## 10. 저장 (`src/persistence`)

- 저장 파일 = `{ formatVersion, name, savedAt, track(좌표 포함), gaConfig, generation, population(유전자·주행상태·결과),
  phase, selection, history(세대별 통계·부모 기록), ghosts, rngState }`.
- 코어 상태가 평범한 데이터이므로 **주행 도중 상태도** 그대로 저장할 수 있다. 저장 시점(세대 경계/주행 중/부모 선택 중)을 파일과 화면에 표시한다.
- 불러오기: 파싱 → 스키마 검증 → 새 상태 객체 구성이 모두 성공한 뒤에만 현재 상태를 교체. 실패하면 현재 실험은 그대로 두고 한국어 오류 메시지 (요구 60).
- 부모 선택 중 저장 → 불러오면 `parentSelection` + 선택 목록 복원, 자동으로 다음 세대로 넘어가지 않음 (요구 47).
- CSV: 세대별 통계 행 단위. 최고 자동차 유전자 별도 JSON 내보내기.
